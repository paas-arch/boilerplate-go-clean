# Крон

Правила — разделы «paas.toml» и «Процессы» правила `.claude/rules/go-clean.md`. Образец — `_examples/cron/cmd/cron/example/main.go`.

Крон — задача по расписанию: панель запускает процесс, он делает один проход и выходит.

1. **Имя.** Строчные латинские буквы, цифры и дефис, с буквы, от 2 до 40 знаков: `daily-report`.
2. **Расписание** — пять полей cron в **UTC**: минута, час, день месяца, месяц, день недели. Человек просит по Москве — вычти 3 часа.

| Нужно | `schedule` |
|---|---|
| Каждые 15 минут | `"*/15 * * * *"` |
| Раз в час, в начале часа | `"0 * * * *"` |
| Каждый день в 03:00 UTC | `"0 3 * * *"` |
| По понедельникам в 09:00 по Москве | `"0 6 * * 1"` |

   `@every`, `@daily` и `TZ=` не поддерживаются.
3. **Логика** — в service (и usecase) по их рецептам. Проход идемпотентен: повторный или пропущенный запуск не ломает данные. Если прошлый запуск ещё идёт, следующий пропускается — значит, проход должен укладываться в интервал.
4. **`cmd/cron/<имя>/main.go`** — скопируй образец и замени сборку зависимостей (база — по шагу 4 `database.md`) и тело прохода. Остаётся как в образце: `signal.NotifyContext`, `return 1` при ошибке (панель покажет запуск упавшим), `return 0` при успехе.
5. **`paas.toml`** — тем же коммитом, запись обязательна: папка без записи не соберётся.

```toml
[[crons]]
name = "<имя>"
description = "<одна строка, что делает, до 120 символов>"
schedule = "0 3 * * *"
size = "small"
```

   Без `enabled` крон включён. `enabled = false` — код в версии, но по расписанию не запускается.
6. **Проверка:** `make run.cron name=<имя>` — проход выполняется и процесс выходит с кодом 0 (`echo $?`). Затем `check.md`.
7. В `ARCHITECTURE.md` добавь крон в дерево `cmd/` одной строкой: что делает и когда.
