# Воркер

Правила — разделы «paas.toml» и «Процессы» правила `.claude/rules/go-clean.md`. Образец — `_examples/worker/cmd/workers/example/main.go`.

Воркер — процесс, который работает всё время: разбирает очередь, ходит по таймеру, слушает внешний источник. Если работа нужна раз в N минут и между запусками процессу нечего держать — это крон (`cron.md`), он дешевле.

1. **Имя.** Строчные латинские буквы, цифры и дефис, с буквы, от 2 до 40 знаков: `sync-orders`.
2. **Логика** — в service (и usecase, если нужна оркестрация) по их рецептам. В `main.go` воркера только сборка зависимостей и цикл.
3. **`cmd/workers/<имя>/main.go`** — скопируй образец и замени:
   - сборку зависимостей — на нужные воркеру (тот же порядок, что в `cmd/api`; база — по шагу 4 `database.md`);
   - тело цикла — на вызов своего сервиса;
   - `interval` — на свой, с комментарием, почему такой.

   Остаётся как в образце: `signal.NotifyContext` по SIGINT/SIGTERM, `select` по `ctx.Done()` в каждом круге, ошибка круга — в журнал без выхода.
4. **`paas.toml`** — тем же коммитом:

```toml
[[workers]]
name = "<имя>"
description = "<одна строка, что делает, до 120 символов>"
enabled = true
replicas = 1
size = "small"
```

   Без `enabled = true` воркер не запустится. Больше одной копии — только если воркер умеет работать параллельно с собой (например, берёт задачи через `SELECT ... FOR UPDATE SKIP LOCKED`).
5. **Новые переменные** воркера — по `env.md`: они общие для всех процессов сервиса.
6. **Проверка:** `make run.worker name=<имя>` — воркер стартует, пишет в журнал, по Ctrl+C выходит за пару секунд. Затем `check.md`.
7. В `ARCHITECTURE.md` добавь воркер в дерево `cmd/` одной строкой: что делает.

Выключить воркер, не удаляя код, — `enabled = false` в его записи. Удалить — папку и запись одним коммитом.
