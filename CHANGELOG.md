# Изменения шаблона бэкенда на Go

По этому файлу панель показывает «Что изменилось» и собирает промпт для ИИ-агента, который переносит обновление в код сервиса. Новые версии — сверху.

Формат версии: заголовок «## vX.Y.Z — ГГГГ-ММ-ДД», строка «Обязательное: да» (без обновления выкатка сломается) или «нет», пункты для людей, подраздел «### Для агента» с шагами переноса. Проверки и смену метки `.paas/template` панель добавляет в промпт сама.

## v0.11.0 — 2026-11-27

Обязательное: нет

- Новый сервис начинается без базы, воркеров и кронов: в шаблоне только API с примером `greetings`. Образцы базы, воркера и крона лежат в `_examples/`, агент берёт их, когда они понадобятся.
- Код, который работает с базой, без `DATABASE_DSN` не стартует и говорит, что базу нужно включить в `paas.toml`. Режим «работаю без базы» с ответом 503 из шаблона убран.
- Вместо шести скилов и семи правил для агента — один скил `go-clean` с рецептами (ручка, база, воркер, крон, переменная, правка `paas.toml`, проверка перед пушем, обновление шаблона) и одно правило `.claude/rules/go-clean.md`. Скил лежит в `.agents/skills/go-clean/` и работает в Claude Code, Codex, Cursor, Kimi Code и Gemini CLI; `GEMINI.md` — ссылка на `CLAUDE.md`.
- `make check` проверяет всё, что проверят CI и сборка, включая `paas.toml`; `make run.cron name=<имя>` запускает крон локально.

### Для агента

1. Удали `.claude/rules/` и `.claude/skills/` сервиса. Скопируй из шаблона `.claude/rules/go-clean.md` и папку `.agents/skills/go-clean/`, затем создай ссылки: `ln -s ../../.agents/skills/go-clean .claude/skills/go-clean` и `ln -s CLAUDE.md GEMINI.md`. Если человек дописывал свои правила или скилы, перенеси их содержание в новые файлы и скажи ему об этом.
2. Скопируй `_examples/` из шаблона целиком, подставив модуль Go сервиса вместо `app.internal`.
3. В `Makefile` добавь цели `run.cron` и `check` из шаблона и впиши их в строку `.PHONY`. Цели базы (`db.up`, `migrate.up`, `migrate.create`), если они есть, оставь.
4. В `CLAUDE.md` перенеси из шаблона: абзац «Что это», пункты договора про `.paas/template`, образы (с `/cron/<имя>` и пустой `migrations/`), базу и образцы воркера и крона, раздел «Команды» и первый пункт «Как устроен код» со ссылками на правило и скил `go-clean`. Свои пункты сервиса оставь.
5. Код сервиса не удаляй и не переписывай: базу, воркеры, кроны, пример `notes` и режим без базы шаблон убрал только из стартовой версии. Если сервис работает с базой и у него есть режим «без базы» (`ErrNoDatabase`, ответ 503), оставь его как есть; перевести на отказ при старте можно отдельной задачей по рецепту `database.md`.
6. Если `migrations/` в сервисе нет, создай её с пустым файлом `.gitkeep`: без неё не соберётся образ `migrator`.

## v0.10.3 — 2026-11-26

Обязательное: нет

- API слушает порт 8080, заданный в коде: панель больше не передаёт переменную `APP_PORT`.

### Для агента

1. В `internal/config/app.go` убери поле `Port` с тегом `env:"APP_PORT"` и добавь константу `Port = 8080`, как в шаблоне. Найди по всему коду обращения к полю `Port` конфига (`cfg.Port` и под другими именами переменной) и замени их на `config.Port`; `go build ./...` должен пройти.
2. Убери `APP_PORT` из `.env.example` и `.env`.
3. Перенеси из шаблона строки про порт в `CLAUDE.md`, `ARCHITECTURE.md` и комментарий про переменные в `paas.toml`.
