# CLAUDE.md

Инструкции для ИИ-агента, который дописывает этот сервис: Claude Code, Codex, Cursor, Kimi, Gemini и других. `AGENTS.md` и `GEMINI.md` — ссылки на этот файл. Язык общения и текстов для людей — русский.

## Что это

Бэкенд на Go, созданный из шаблона `go-backend` панели paas. Панель собирает его и выкатывает на сервер, а по `paas.toml` выдаёт базу Postgres, запускает воркеры и кроны. Код — твой. В шаблоне только API с примером `greetings`: замени его своим. Базы, воркеров и кронов в шаблоне нет — добавляй их, когда понадобятся; образцы лежат в `_examples/`.

## Договор с панелью — не нарушай

Панель выкатывает сервис, не читая код, по этим соглашениям. Если их сломать, сборка или выкатка упадёт.

- **`.paas/template` и `CHANGELOG.md` — метки шаблона.** `.paas/template` хранит версию шаблона, из которой код сервиса; её ставит панель, и по ней она предлагает обновление промптом для агента. Меняй её только последним шагом такого промпта. `CHANGELOG.md` — что нового в версиях шаблона. `.agents/`, `.claude/` и `_examples/` обновляются вместе с шаблоном.
- **`paas.toml` — настройки сервиса на сервере.** Число копий, размер, база, переменные, воркеры и задачи по расписанию задаёт только этот файл; панель читает его при раскатке. Неизвестный ключ — ошибка: сборка проверяет файл и с ошибкой не соберёт версию. `name` не меняй: он равен имени репозитория. Формат — комментарии в самом файле и раздел «paas.toml» правила `.claude/rules/go-clean.md`.
- **Не меняй `Dockerfile` и `.github/workflows/release.yml`.** По ним каждый пуш в `main` собирает образы `ghcr.io/<организация>/<репо>/api`, `/workers/<имя>`, `/cron/<имя>` и `/migrator` с одним тегом версии. Папка `migrations/` нужна сборке, даже пустая: не удаляй её.
- **В `cmd/` только `cmd/api`, `cmd/workers/<имя>` и `cmd/cron/<имя>`.** Имя — строчные латинские буквы, цифры и дефис. Других папок в `cmd/` не заводи: их никто не запустит.
  - Новый воркер — папка `cmd/workers/<имя>` с `main.go`. Запускается он, только когда в `paas.toml` есть запись `[[workers]]` с его `name` и `enabled = true`: заводи её тем же коммитом; там же копии, размер и `description` — одна строка о том, что делает воркер, её видно в панели.
  - Новый крон (задача по расписанию) — папка `cmd/cron/<имя>` с `main.go`, который делает один проход и выходит. Запись `[[crons]]` с тем же `name` и `schedule` (UTC) обязательна, заводи её тем же коммитом; `enabled = false` выключает крон, `description` — одна строка о том, что он делает.
  - Образцы — `_examples/worker` и `_examples/cron`, рецепты — `worker.md` и `cron.md` скила `go-clean`.
- **API слушает порт 8080.** Порт не меняй: панель ждёт сервис на нём.
- **База — по `paas.toml`.** `[postgresql] enabled = true` — и раскатка выдаст базу, применит миграции и передаст её адрес в `DATABASE_DSN`; переменную не переименовывай. Код, который работает с базой, без `DATABASE_DSN` не стартует и пишет, что базу нужно включить в `paas.toml`.
- **`/health` отвечает 200, пока процесс жив.** Он встроен в `internal/util/webserver`; не убирай его и не занимай этот путь.
- **Миграции — в `migrations/`, только вперёд.** Они применяются перед каждой выкаткой, пока ещё работает прежняя версия кода. Применяет их образ `migrator`, сам сервис миграций не запускает.
- **Ручки API — под `/api/`.** Веб-приложение проекта пересылает бэкенду только такие пути.
- **Остановка по сигналу.** Процесс завершается по SIGTERM за несколько секунд: так панель выкатывает новую версию без потерь.
- **Логи — в стандартный вывод.** Панель показывает их на странице сервиса. Значения секретов в логи не пиши.

Свои настройки (ключи внешних сервисов и т.п.) добавляй переменными окружения в `internal/config` и тем же коммитом объявляй в `[env_vars]` файла `paas.toml`: со значением — обычная переменная, с пустой строкой — секрет, его значение вводят в панели. `DATABASE_DSN` и `BACKEND_URL` задаёт панель, имя `APP_PORT` занято: в файле их не объявляй. Значения секретов человек вводит в панели на вкладке «Секреты».

## Команды

- `cp .env.example .env && make run` — API на `:8080`.
- `make run.worker name=<имя>`, `make run.cron name=<имя>` — воркер и один запуск крона.
- `make check` — перед каждым пушем: формат, кодогенерация и моки, линтер, тесты и `paas.toml` той же программой, что сборка.
- `make codegen` — после любой правки `api/schema.yaml`: пересобирает `internal/generated/`.
- `make generate` — моки после правки любого `deps.go`.
- Команды базы (`make db.up`, `migrate.up`, `migrate.create`) появляются, когда сервису добавили базу.

## Как устроен код

- Поток вызова `handler → usecase → service → repository → Postgres`.
- **Правила кода и `paas.toml` — `.claude/rules/go-clean.md`.** Прочитай файл до первой правки кода: Claude Code подгружает его сам, остальные агенты — нет.
- **Пошаговые рецепты** (ручка, база, воркер, крон, переменная, проверка, обновление шаблона) — скил `go-clean` в `.agents/skills/go-clean/` (для Claude Code — ссылка `.claude/skills/go-clean`). Если агент не подхватил скил сам, открой `SKILL.md` оттуда: в нём оглавление, рецепт — отдельный файл рядом.
- Контракт API задаёт только `api/schema.yaml`; код ручек и DTO из него генерируется.
- Подробности и разделы, которые обновляются вместе с кодом, — `ARCHITECTURE.md`.

## Комментарии в коде

- Комментарий — одна строка. Объясняем «почему», а не «что». Исключение — нумерованные шаги в usecase.

## Скилы в работе

- Возникли вопросы по задаче — задавай их человеку по одному.
