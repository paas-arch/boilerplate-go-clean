# Слой service

- Пакет `internal/service/<mechanism>` (`notebook`) — доменный механизм поверх одного или нескольких клиентов и репозиториев. SQL в сервисе не пишется: запросы живут в `internal/repository/<таблица>`. Файлы: `deps.go`, `service.go`, `service_test.go`, `_mocks/`.
- В сервис инжектятся только клиенты и репозитории. Сервис в сервис не инжектится: когда нужны два сервиса, их связывает usecase.
- `type Service struct` + `New(...)`; настройки (TTL, лимиты) — аргументами `New` из конфига или константами пакета с комментарием-«почему», а не чтением env.
- Сервис собирает entity (проставляет вычисляемые поля, время, хеши) и прячет от usecase детали хранения. Методы называются доменными глаголами (`Add`, `ListLatest`), а не CRUD-ом репозитория.
- Ошибки: обёртка `fmt.Errorf("failed to <действие>: %w", err)`; доменные исходы — экспортируемые sentinel `var ErrXxx = errors.New("...")` с комментарием, зачем они. `errx` здесь не используется.
- «Не найдено» у внешнего API сервис переводит в свой sentinel, чтобы usecase не разбирал ошибки клиентов.
- Внешний провайдер — интерфейс в `deps.go` (`provider`), реализация выбирается в `main.go`.
