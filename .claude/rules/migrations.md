# Миграции

- Файл `migrations/NNNNN_название.sql` со следующим номером (`00002_add_title_to_notes.sql`): `make migrate.create name=...` или руками.
- Миграции применяет образ `migrator` перед каждой выкаткой; если миграция упала, панель оставляет сервис на прежней версии и показывает лог.
- Только вперёд: раздел `-- +goose Down` не пишется. Ошибку в применённой миграции исправляет следующая миграция.
- Формат goose: `-- +goose Up`, затем `-- +goose StatementBegin` … `-- +goose StatementEnd`.
- Каждая миграция идёт в транзакции. Команды, которые Postgres в транзакции не выполняет (`CREATE INDEX CONCURRENTLY`), запрещены: упавшая миграция оставила бы след.
- Миграция должна проходить на старой версии кода: пока она идёт, работают прежние приложения. Удалить колонку — две выкатки: сначала код перестаёт её читать, потом миграция удаляет.
- Одна таблица — одна миграция. ENUM-тип живёт в миграции таблицы, которая его использует. Связанные таблицы идут разными файлами в порядке FK.
- Ключ — `bigserial PRIMARY KEY` (uuid только для публичных непредсказуемых id); время — `timestamp NOT NULL DEFAULT NOW()`; закрытые наборы значений — `CREATE TYPE ... AS ENUM`, а не boolean и не varchar.
- Индекс заводим под конкретный запрос и пишем над ним одну строку, какой запрос он обслуживает.
- Новая колонка на существующей таблице — `NULL` или с `DEFAULT`, чтобы миграция прошла на живых данных.
- Проверка: `make db.up migrate.up && make run` — сервис стартует, новая версия есть в `goose_db_version`.
