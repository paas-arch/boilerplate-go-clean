# go-clean

Правила, по которым пишется код и `paas.toml`, — `.claude/rules/go-clean.md`; договор с панелью — `CLAUDE.md`. Здесь — что делать по шагам. Открой только рецепт под задачу: файлы лежат рядом с этим.

| Задача | Рецепт |
|---|---|
| Новая ручка API или правка существующей | `handler.md` |
| Сценарий с проверкой ввода, бизнес-ошибкой или несколькими сервисами | `usecase.md` |
| Доменная логика поверх клиентов и таблиц | `service.md` |
| Сервису впервые нужна база | `database.md` |
| Новая таблица, колонка, индекс | `migration.md`, затем `repository.md` |
| Новый запрос к существующей таблице | `repository.md` |
| Интеграция с внешним API (платежи, почта, чужой сервис) | `client.md` |
| Фоновый процесс, который работает всё время | `worker.md` |
| Задача по расписанию | `cron.md` |
| Новая настройка, ключ или секрет | `env.md` |
| Копии, размер, база, описание сервиса | `paas-toml.md` |
| Промпт панели «Обнови сервис с шаблона …» | `template-update.md` |
| Перед каждым пушем в `main` | `check.md` |

Типичная фича «новая сущность с ручками»: (`database.md`, если базы ещё нет) → `migration.md` → `repository.md` → `service.md` → `usecase.md` → `handler.md` → `check.md`.

В шаблоне нет базы, воркеров и кронов: их образцы — в `_examples/`, рецепты говорят, что оттуда копировать.

Задача закончена, когда `make check` зелёный, а `ARCHITECTURE.md` обновлён в разделах, которые назвал рецепт.
